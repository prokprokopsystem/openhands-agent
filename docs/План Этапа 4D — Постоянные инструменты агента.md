# Этап 4D — Постоянные управляемые инструменты агента

**Версия:** 1.2 (28 июля 2026)
**Статус:** 🔄 Пакет реализован; установка допускается после независимой проверки корректирующего коммита

---

## 1. Цель

Предоставить агенту Canvas постоянные, расширяемые и безопасные инструменты
для самостоятельной работы над проектом без ручной настройки каждого действия.

## 2. Модель угроз

| Угроза | Мера |
|--------|------|
| Агент Canvas скомпрометирован → произвольные команды | Broker проверяет каждую команду против реестра; неизвестные команды отклоняются |
| Broker обойдён | SSH forced command (`command=...` в `authorized_keys`) ограничивает shell одной командой wrapper |
| Wrapper обойдён | Пользователь `openhands-broker` на хосте не имеет прав на критичные операции |
| Секрет перехвачен в модели | Секрет не передаётся агенту — broker подставляет его на хосте по имени |
| Компрометация одного ключа | Для mini-server и VPS — отдельные ключи, отдельные пользователи, отдельные реестры |
| Broker отказывает | Каждый вызов идемпотентен или имеет fallback; журнал позволяет диагностировать |

## 3. Архитектура

```
Canvas (контейнер)
  │ SSH (ключ mini-server)
  ▼
sshd → authorized_keys (command="/usr/local/lib/openhands-broker/broker-wrapper.sh")
  │
  ▼
broker-wrapper.sh
  ├─ 1. Парсит команду: <инструмент> [параметры...]
  ├─ 2. Проверяет инструмент в реестре /etc/openhands-broker/tools.yaml
  ├─ 3. Проверяет уровень риска → допуск
  ├─ 4. Подставляет секреты из /etc/openhands-broker/secrets/ (не через аргументы)
  ├─ 5. Журналирует: timestamp, инструмент, параметры (без секретов), exit code
  ├─ 6. Выполняет команду (dry-run если --dry-run)
  ├─ 7. Проверяет результат (verify)
  ├─ 8. При неудаче — выполняет rollback (если есть)
  └─ 9. Возвращает stdout/stderr + exit code
```

## 4. Компоненты

### 4.1. Broker-wrapper (на хосте)

**Расположение:** `/usr/local/lib/openhands-broker/broker-wrapper.sh`

Обязанности:
- Единственная точка входа через SSH forced command
- Читает реестр `/etc/openhands-broker/tools.yaml`
- Проверяет параметры, уровень, секреты
- Исполняет команду с подстановкой
- Журналирует в `/var/log/openhands-broker/`

### 4.2. Реестр инструментов

**Расположение:** `/etc/openhands-broker/tools.yaml`

Формат — YAML. Один файл, секции по серверам.
Добавление инструмента — новая запись в YAML. Без изменения wrapper.

### 4.3. Секреты

**Расположение:** `/etc/openhands-broker/secrets/`

Файлы: `TELEGRAM_BOT_TOKEN`, `DEEPSEEK_API_KEY`, `GITHUB_TOKEN`, и т.д.
Права: `root:openhands-broker`, `640`.
Агент обращается по имени: `{{secret:TELEGRAM_BOT_TOKEN}}` → wrapper подставляет значение.
Значение **не** передаётся в модель, не пишется в журнал (заменяется на `***`).

### 4.4. Журнал

**Расположение:** `/var/log/openhands-broker/`

- `actions.log` — JSONL: `{"ts":"...","tool":"...","params":"...","exit_code":0,"duration_sec":1,"status":"OK"}`
- Параметры в логах: значения заменены (без секретов)
- `error.log` — только ошибки
- Ротация: logrotate weekly, keep 4

### 4.5. SSH-ключ

- Ключ генерируется отдельно для mini-server и VPS
- Публичный ключ добавляется в `~openhands-broker/.ssh/authorized_keys`
- Обязательный префикс (ограничения):
  ```
  no-port-forwarding,no-agent-forwarding,no-X11-forwarding,no-pty,
  command="/usr/local/lib/openhands-broker/broker-wrapper.sh"
  ```
- Ключ без forced command запрещён
- Shell пользователя: `/bin/bash` — требуется sshd для запуска forced command; интерактивный shell блокируется параметрами ключа
- Приватный ключ хранится в `/srv/openhands-agent/secrets/broker-mini-server.key` (root:root, 600)
- Canvas монтирует только файл `/srv/openhands-agent/secrets/broker-mini-server.key` в режиме read-only; остальные host secrets не видны контейнеру
- Ключ читается из `/secrets/broker-mini-server.key` внутри контейнера

## 5. Реестр инструментов (начальный)

### 5.1. Mini-server

```yaml
server: mini-server
user: openhands-broker
tools:
  - name: system_status
    description: Проверка статуса systemd-службы
    risk: A
    params:
      service: { type: string, required: false, default: "openhands-agent" }
    execute: "systemctl status {{service}} --no-pager -l 2>&1 | head -80"
    verify: null
    rollback: null
    secrets: []

  - name: journal_logs
    description: Чтение журнала systemd-службы
    risk: A
    params:
      service: { type: string, required: false, default: "openhands-agent" }
      lines: { type: integer, required: false, default: 50 }
    execute: "journalctl -u {{service}} -n {{lines}} --no-pager 2>&1"
    verify: null
    rollback: null
    secrets: []

  - name: docker_ps
    description: Список запущенных контейнеров
    risk: A
    execute: "docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}' 2>&1"
    verify: null
    rollback: null
    secrets: []

  - name: docker_compose_ps
    description: Статус проекта Docker Compose
    risk: A
    params:
      project: { type: string, required: false, default: "/srv/openhands-agent/deployment" }
    execute: "docker compose -f {{project}}/compose.yaml ps 2>&1"
    verify: null
    rollback: null
    secrets: []

  - name: disk_usage
    description: Использование диска
    risk: A
    execute: "df -h / /srv 2>&1"
    verify: null
    rollback: null
    secrets: []

  - name: memory_usage
    description: Использование памяти
    risk: A
    execute: "free -h 2>&1"
    verify: null
    rollback: null
    secrets: []

  - name: service_restart
    description: Перезапуск systemd-службы проекта
    risk: B
    params:
      service: { type: string, required: true }
    check: "systemctl is-active {{service}} 2>&1"
    execute: "sudo systemctl restart {{service}} 2>&1"
    verify: "systemctl is-active {{service}} 2>&1 | grep -q active"
    rollback: "sudo systemctl restart {{service}} 2>&1"
    secrets: []

  - name: service_stop
    description: Остановка systemd-службы проекта
    risk: B
    params:
      service: { type: string, required: true }
    check: "systemctl is-active {{service}} 2>&1"
    execute: "sudo systemctl stop {{service}} 2>&1"
    verify: "systemctl is-active {{service}} 2>&1 | grep -q inactive"
    rollback: "sudo systemctl start {{service}} 2>&1"
    secrets: []

  - name: service_start
    description: Запуск systemd-службы проекта
    risk: B
    params:
      service: { type: string, required: true }
    execute: "sudo systemctl start {{service}} 2>&1"
    verify: "systemctl is-active {{service}} 2>&1 | grep -q active"
    rollback: "sudo systemctl stop {{service}} 2>&1"
    secrets: []

  - name: backup_create
    description: Создать резервную копию проекта
    risk: B
    execute: "sudo /usr/local/bin/openhands-backup.sh 2>&1"
    verify: "ls -lt /mnt/amnesia-backup/openhands-agent/daily/ 2>&1 | head -3"
    rollback: null
    secrets: []

  - name: docker_compose_logs
    description: Логи Docker Compose проекта
    risk: A
    params:
      lines: { type: integer, required: false, default: 50 }
    execute: "docker compose -f /srv/openhands-agent/deployment/compose.yaml logs -n {{lines}} --no-color 2>&1 | tail -{{lines}}"
    verify: null
    rollback: null
    secrets: []

  - name: ping
    description: Проверка доступности хоста
    risk: A
    execute: "echo pong"
    verify: null
    rollback: null
    secrets: []

  - name: validate_runtime
    description: Запуск валидации runtime
    risk: A
```

## 6. Переиспользуемые существующие компоненты

| Компонент | Использование в 4D |
|-----------|-------------------|
| `validate-runtime.sh` | Pre-flight check перед операциями уровня B |
| `apply-egress-rules.sh` | Reference для изоляции — не дублировать, можно вызывать через broker |
| `run-supervised.sh` | Паттерн supervisor для будущих расширений |
| `health-watchdog.sh` | Паттерн watchdog |
| `seed-config.sh` | Паттерн подстановки секретов из шаблонов |
| `openhands-backup.sh` | Вызывается через broker как `backup_create` |
| `openhands-tg-gateway.service` | Не изменять, gateway уже работает |
| secrets/ | Secrets остаются на хосте, broker читает оттуда же |
| `validate-static.sh` | Статические проверки конфигов |

## 7. Формат вызова из Canvas

```bash
# Без параметров (инструмент с default-параметрами)
ssh -i /secrets/broker-mini-server.key \
    -o StrictHostKeyChecking=accept-new \
    openhands-broker@10.89.0.1 \
    system_status

# С параметрами
ssh ... openhands-broker@10.89.0.1 \
    'journal_logs service=openhands-agent lines=20'

# Dry-run
ssh ... openhands-broker@10.89.0.1 \
    'service_restart service=openhands-agent.service --dry-run'
```

## 8. Установка broker на хост

Требования: Git-репозиторий, зафиксированный коммит, python3 + PyYAML.
Никакие команды не выполняются из незафиксированного репозитория.

```bash
# На mini-server:
git clone --branch fix/canonical-deployment <repo> /tmp/openhands-stage
cd /tmp/openhands-stage
# Проверить что git show HEAD — нужный коммит
sudo bash deployment/broker/setup-broker.sh $(git rev-parse HEAD)
# Добавить публичный SSH-ключ в /home/openhands-broker/.ssh/authorized_keys
# с префиксом: no-port-forwarding,...,command="/usr/local/lib/openhands-broker/broker-wrapper.sh"
sudo visudo -cf /etc/sudoers.d/openhands-broker
# Проверить: ssh -i <key> -o StrictHostKeyChecking=accept-new openhands-broker@10.89.0.1 ping
```

Firewall открывает для подсети Canvas только `10.89.0.1:22`, одновременно в
`OPENHANDS-EGRESS` и `OPENHANDS-INPUT`. Остальные порты mini-server остаются
закрыты.

## 9. Sudo-правила

```
# /etc/sudoers.d/openhands-broker
# Только указанные команды, без пароля
openhands-broker ALL=(root) NOPASSWD: /usr/bin/systemctl restart openhands-agent.service
openhands-broker ALL=(root) NOPASSWD: /usr/bin/systemctl stop openhands-agent.service
openhands-broker ALL=(root) NOPASSWD: /usr/bin/systemctl start openhands-agent.service
openhands-broker ALL=(root) NOPASSWD: /usr/bin/systemctl status openhands-agent.service
openhands-broker ALL=(root) NOPASSWD: /usr/local/bin/openhands-backup.sh
openhands-broker ALL=(root) NOPASSWD: /srv/openhands-agent/deployment/scripts/validate-runtime.sh
```

## 10. Связанные DEC

- **DEC-001** (systemd lifecycle) — не нарушается, broker не заменяет systemd
- **DEC-002** (firewall до старта) — broker не стартует контейнер, только управляет
- **DEC-005** (выделенные цепочки) — SSH broker не требует изменения egress
- **DEC-015** (секреты вне Git) — соблюдается, ключи broker в secrets/, не в Git
- **DEC-022** (шлюз разрешений) — broker реализует технический шлюз на уровне хоста
