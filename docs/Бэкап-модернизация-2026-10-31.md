# Модернизация backup: безопасная ротация, пропуск без изменений, согласованные базы (31.10.2026)

Статус: **изменение подготовлено и проверено, но НЕ установлено.** Установка требует root,
которого у агента нет (`sudo` требует интерактивный пароль; брокеру разрешён только *запуск*
`/usr/local/bin/openhands-backup.sh`, не запись). Ограничения не обходились: ни `sudo`,
ни `docker`, ни иные пути повышения привилегий не использовались. Реальный backup не
запускался, существующие архивы не читались, не перемещались и не удалялись, служба,
таймер, Compose, профили и память OpenHands не изменялись.

## 1. Что и почему изменено

Новая версия — `deployment/scripts/openhands-backup.sh` (396 строк,
`sha256 b3f0ee233ad69219cc92fffb0f8fef203604c048c8c45e3dd72083a1c07ab4fc`).
Это та же служба, тот же таймер, те же имена архивов (`daily/openhands_YYYY-MM-DD.tar.gz`,
`weekly/openhands_YYYY-Wnn.tar.gz`), тот же `backup.log`, тот же `-C /srv openhands-agent`.
Новая система не создавалась.

Фактическое поведение прежней версии подтверждено владельцем (`sudo cat`, скриншот, PR №4,
коммит `6b6f767`):

```bash
tar czf "$DAILY_FILE" $EXCLUDE -C /srv openhands-agent 2>&1 | tail -1 || true
tar tzf "$DAILY_FILE"            # проверка
cp "$DAILY_FILE" "$WEEKLY_FILE"  # по воскресеньям
find "${BACKUP_DIR}/daily"  -name '*.tar.gz' -mtime +7  -delete
find "${BACKUP_DIR}/weekly" -name '*.tar.gz' -mtime +28 -delete
```

| Проблема | Что сделано |
|---|---|
| `-mtime +7` считает возраст от «сегодня»: после простоя >7 дней первый же запуск удаляет историю, возможна потеря **всех** копий | Возраст считается от самой свежей копии уровня; самая свежая и эталонная проверенная копия защищены явно; уровень не опускается ниже минимума (daily 3, weekly 2) |
| Удаление выполняется независимо от результата текущего прогона | Ротация запускается только после чистого и проверенного прогона; при любой ошибке архивы не удаляются |
| Первый запуск новой версии мог бы удалить существующие архивы | Bootstrap: первый прогон новой логики ничего не удаляет |
| `tar ... 2>&1 \| tail -1 \|\| true` маскирует ошибку `tar` (`|| true` гасит код возврата конвейера) | `tar` без конвейера, код возврата проверяется явно; `rc>=2` — провал прогона, `rc=1` («файл изменился при чтении») фиксируется как предупреждение и блокирует ротацию |
| Каждый день пишется полный 4,4 МБ архив, даже если данных не изменилось | Отпечаток существенных данных; при совпадении и наличии проверяемого архива — `SKIP daily`, запись не выполняется |
| Работающие SQLite-базы (включая локальное хранилище встроенного Qdrant) копируются как обычные файлы | Штатный SQLite Backup API (`sqlite3.Connection.backup`), затем `PRAGMA integrity_check` копии; исходная база исключается из прохода `tar`, поэтому оригинал и его копия не попадают в один архив |

### 1.1 Отпечаток: что считается существенным

Учитываются: `config/agent-canvas/conversations` (разговоры), `docs`, Mem0 и хранилище
памяти (`store/`), все SQLite-базы (логический хеш по `iterdump`, не зависит от свободных
страниц), встроенный Qdrant (`qdrant_db/collection/*/storage.sqlite`), символьные ссылки
(по цели).

Игнорируются: `bash_events` (журнал команд Canvas), `cache/`, `venv/`,
`store/models` (кэш fastembed), `__pycache__`, `node_modules`, `.git`,
`owner_lease.json` (heartbeat беседы), `*.lock`, `*.tmp`, `*.swp`, `*.pyc`,
`-journal`/`-wal`/`-shm`.

Списки исключений для `tar` и для расчёта отпечатка заданы в одном месте скрипта
(`EXCL_DIR_NAMES`, `EXCL_FILE_PATTERNS`) — расхождение между ними было реальным дефектом,
найденным тестами (см. §3.1).

Если отпечаток получить не удалось, это **не** трактуется как «изменений нет»: прогон
продолжается как полный backup, а ротация блокируется.

### 3.1 Дефекты, найденные тестами и исправленные

1. `owner_lease.json` и файлы по маскам исключались из отпечатка, но попадали в архив —
   рассинхронизация списков. Введён единый `EXCL_FILE_PATTERNS`, добавленный и в `tar`.
2. Неверное ожидаемое число записей: копии баз заменяют оригиналы один к одному,
   поэтому `expected = entries`, а не `entries + staged`.
3. Путь стейджинга баз не содержал префикс `openhands-agent`, из-за чего `tar --append`
   не находил файлы.
4. Символьные ссылки не учитывались в отпечатке, но попадали в архив (счётчик расходился).

## 4. Процедура установки (для владельца сервера, требует root)

Выполнять на `mini-server` в одном сеансе. Ничего не удаляется.

```bash
# 0. Пути и проверка, что внешний диск смонтирован
sudo mountpoint -q /mnt/amnesia-backup && echo "disk OK" || echo "STOP: диск не смонтирован"

# 1. Сохранить исходный скрипт для отката и зафиксировать контрольную сумму
sudo cp -a /usr/local/bin/openhands-backup.sh \
        "/usr/local/bin/openhands-backup.sh.bak-$(date -u +%Y%m%dT%H%M%SZ)"
sudo sha256sum /usr/local/bin/openhands-backup.sh*
sudo cat /usr/local/bin/openhands-backup.sh          # исходный текст — для сверки

# 2. Сохранить эталон сегодняшнего архива вне каталогов ротации
#    (ротация смотрит только daily/ и weekly/, поэтому файл в корне BACKUP_DIR не тронется)
D=/mnt/amnesia-backup/openhands-agent/daily/openhands_$(date -u +%F).tar.gz
[ -f "$D" ] && sudo cp -a "$D" \
  "/mnt/amnesia-backup/openhands-agent/archive-before-modernisation-$(date -u +%F).tar.gz"

# 3. Установить новую версию из репозитория (файл уже получен из PR №4)
sudo install -m 0755 -o root -g root \
     /srv/openhands-agent/deployment/scripts/openhands-backup.sh \
     /usr/local/bin/openhands-backup.sh.new
sudo bash -n /usr/local/bin/openhands-backup.sh.new   # синтаксис
sudo python3 -c 'import sqlite3; print(sqlite3.sqlite_version)'   # нужен модуль sqlite3
sudo command -v flock gzip mountpoint tar stat python3 || echo "STOP: нет утилиты"

# 4. Сверить с прежним текстом и только потом включить
sudo diff -u /usr/local/bin/openhands-backup.sh.bak-* /usr/local/bin/openhands-backup.sh.new | less
sudo mv /usr/local/bin/openhands-backup.sh.new /usr/local/bin/openhands-backup.sh

# 5. Один контролируемый запуск существующей службы
sudo systemctl start openhands-backup.service
sudo systemctl status openhands-backup.service --no-pager -l
sudo tail -n 25 /mnt/amnesia-backup/openhands-agent/backup.log
```

### Шаг 5 — что должно быть в журнале (норма)

```
SCAN <N> entries, <M> sqlite staged, 0 failed, fp <hash>
START daily → …/daily/openhands_<дата>.tar.gz
OK daily …/daily/openhands_<дата>.tar.gz (…M)
ROTATION skipped — first run of new retention logic, existing archives preserved
DONE
```

`ROTATION skipped — first run…` — ожидаемо и обязательно: при внедрении ничего не удаляется.

### Шаг 6 — проверка результата

```bash
B=/mnt/amnesia-backup/openhands-agent
A=$B/daily/openhands_$(date -u +%F).tar.gz

# 6.1 архив читается целиком
sudo tar tzf "$A" >/dev/null && echo "tar OK"

# 6.2 число записей совпадает с журналом (SCAN entries)
sudo tar tzf "$A" | grep -v '/$' | wc -l

# 6.3 сверка состава с архивом до модернизации (не должно быть потерь разделов)
OLD=$B/archive-before-modernisation-$(date -u +%F).tar.gz
[ -f "$OLD" ] && diff <(sudo tar tzf "$OLD" | sed 's#/.*##' | sort -u) \
                     <(sudo tar tzf "$A"   | sed 's#/.*##' | sort -u)

# 6.4 все базы в архиве целы и читаются
sudo bash -c 'T=$(mktemp -d); tar xzf '"$A"' -C $T; python3 - "$T" <<PY
import glob, sqlite3, sys
bad = n = 0
for p in sorted(glob.glob(sys.argv[1]+"/**/*.db", recursive=True) +
                glob.glob(sys.argv[1]+"/**/*.sqlite", recursive=True)):
    c = sqlite3.connect(p); v = c.execute("pragma integrity_check").fetchone()[0]; c.close()
    n += 1
    if v != "ok": bad += 1; print("BAD", p, v)
print(f"{n} баз, повреждено {bad}"); sys.exit(1 if bad else 0)
PY
rm -rf $T'

# 6.5 оригинал и его копия не задвоены (каждый путь ровно один раз)
sudo tar tzf "$A" | grep -v '/$' | sort | uniq -d      # пусто — норма

# 6.6 прежние архивы сохранены
sudo ls -l $B/daily $B/weekly
sudo ls -l $B/archive-before-modernisation-*.tar.gz

# 6.7 таймер продолжает работать
systemctl list-timers openhands-backup.timer --no-pager
```

### Шаг 7 — повторить запуск и убедиться в пропуске

## 5. Откат

```bash
# вернуть прежний скрипт (daemon-reload не нужен: это скрипт, не юнит)
sudo cp -a /usr/local/bin/openhands-backup.sh.bak-<метка> /usr/local/bin/openhands-backup.sh
sudo systemctl start openhands-backup.service     # проверка прежнего поведения
```

Отдельно: удаление `$BACKUP_DIR/.state/` возвращает «первый запуск» — следующий прогон
сделает полный архив и ничего не удалит. Состояние правки изолировано в этом каталоге.
Уже созданные архивы переживают откат; формат имён и структура архива не менялись,
поэтому прежняя процедура восстановления (`tar xzf … -C … ; rsync`) продолжает работать.

## 7. Границы: что осталось непроверенным

1. **Установка не выполнена** — нет root. Причина: `sudo` требует интерактивный пароль
   (`sudo -n true` → «interactive authentication is required»); NOPASSWD выдан только на
   подкоманды `codex-mini-server-admin`; брокеру разрешён лишь запуск
   `/usr/local/bin/openhands-backup.sh`, но не запись в него.
2. **Реальный архив не создавался и не читался** — каталог `0700 root`.
3. **Точный состав производственного архива не сверен** — сравнение составов и размеров
   вынесено в шаг 6.3 процедуры (выполняется владельцем).
4. **Еженедельный ярус** в этой сессии не проверялся по календарю: 31.10 — суббота,
   ветка воскресенья не срабатывает. Логика проверена тестами на песочнице.
5. Остаётся прежним (не входило в задание): архивы не шифруются, а в `/srv/openhands-agent`
   лежат `secrets/` и `ssh-client/` — то есть ключи попадают в незашифрованный `tar.gz`
   в каталоге `0700`. Это существующее поведение, отдельное решение владельца.
