## 8. Переполнение внешнего диска и риск ротации

**Переполнения нет и в обозримом будущем не будет.** Завтрашний архив вырастет с 4.4M до ~322M (в 73 раза). Худший случай ротации: 7 daily + 4 weekly = 11 полных копий × 322M ≈ **3.5G**, то есть 1.5% свободных 233G. Даже десятикратный рост даёт 35G.

Реальные риски — не объём:

1. **Назавтра архив в 73 раза больше из-за мусора.** 576 из 577M в `/projects` — `venv` и скачанные модели. 11 копий × ~300M ≈ 3.3G из 3.5G — переархивация переустанавливаемого окружения.
2. **Окно хранения ≈ две недели.** Ежедневные живут 7 дней, недельные удаляются раньше задокументированных 28 дней (20.10 и 27.10 удалено по одной при возрасте 9–23 дня). Самая старая живая копия — W42 от 18.10. **Всё, что старше ~13 дней, уже невозможно восстановить.**
3. **Что именно утрачивается при удалении.** Каждый архив — полная копия, а не инкремент. При удалении daily теряется целиком тот день: разговоры, события, состояние памяти на ту дату. Промежуточных версий между двумя сохранившимися копиями нет — при удалении W42 теряется период 18–25.10 безвозвратно.
4. **Уже утрачено.** Каталогов разговоров старше текущей пары на диске нет, а копии июля–сентября ротированы. Историю переписки за июль–октябрь восстановить не из чего, кроме случайно уцелевших недельных.
5. **Один носитель.** Падение `/dev/sdb1` уничтожает весь архив; второй копии нет.
6. **Секреты в открытом архиве.** `secrets/.env`, приватный ключ брокера, `secret-key.txt` и ключи LLM в `profiles/*.json` лежат в незашифрованном `tar.gz`. Отдельный GPG-архив, обещанный планом 5A, не реализован. Частичная компенсация — каталог `0700 root:root`, но при переносе диска или смене владельца защита исчезает.
7. **Несогласованная копия.** SQLite/Qdrant копируются на живой записи; архив может содержать БД в промежуточном состоянии. Проверить это сейчас нельзя: содержимое архива недоступно.

## 9. Минимальная схема долговременного хранения (предложение, НЕ внедрено)

Ничего нового не добавляем: та же служба, тот же таймер, тот же диск.

1. **Исключить воспроизводимое из tar** — единственная правка, дающая основной эффект: `--exclude='*/venv' --exclude='*/store/models' --exclude='*/cache' --exclude='__pycache__'`. Архив падает с ~322M до ~16M, а значит долгое хранение становится дешёвым. Это не удаление данных: `venv` восстанавливается из зафиксированных зависимостей, модели — скачиванием.
2. **Месячный ярус без дубликатов — жёсткие ссылки.** На ext4 `ln weekly/openhands_2026-W43.tar.gz monthly/openhands_2026-10.tar.gz` занимает **0 байт** (общий inode). Хранение 12 месяцев × 0 байт вместо 12 полных копий. Требование «не дублировать одни и те же файлы отдельными полными архивами» выполняется буквально.
3. **Решения — в Git, а не в архиве.** `Решения.md` и `docs/` уже версионируются; архив не должен их дублировать. Архив отвечает за сырые разговоры и состояние, Git — за историю решений (это же и есть канонический источник из M3).
4. **Проверяемость.** Раз в месяц `tar tzf` + извлечение одного файла со сверкой sha256 (процедура проверена в разделе 7). Хеши и размеры — в `manifests/`, который уже существует на диске.
5. **Доступ на чтение без root.** `chmod g+r` на месячный/недельный ярус и `setgid` на каталог — чтобы проверку и холодный поиск можно было делать от `igor`, не поднимая привилегий.
6. **Второй носитель.** Не вводится сейчас; отмечаю как обязательное условие перед объявлением схемы долговременной.

Итог: та же служба, одна правка в скрипте (исключения) и один дешёвый ярус хранения; ни новых служб, ни новых архивов полного размера.

## 10. Поиск в старых разговорах без загрузки в DeepSeek

Хранилище уже разбито на мелкие файлы: **одно событие — один JSON** (`conversations/<id>/events/event-NNNNN-<uuid>.json`), в среднем ~7 КБ. Целый чат (14M) — это примерно 3.5–4 млн токенов, в контекст не влезает и не должен.

Три уровня, все на существующих средствах:

- **Уровень 0, горячий (15M).** `rg -l '<термин>' conversations/*/events/` → возвращает только пути. Читаем 3–5 файлов по ~7 КБ. В контекст попадают десятки килобайт вместо 14 МБ.
- **Уровень 1, смысловой.** Те же мелкие файлы индексируются уже установленным Mem0 с локальным fastembed (`add(infer=False)`, без вызовов LLM, как в M2). В payload: `conversation_id`, путь к файлу события, метка времени, проект. Поиск возвращает 5 фрагментов с указателями; модель видит только их, а проверить факт можно открытием названного файла.
- **Уровень 2, холодный (в архивах).** Чтение одного файла без полной распаковки: `tar xzOf archive '*<conversation>/events/event-00042*.json'`. Для регулярного поиска — разовая распаковка только текстовых поддеревьев в отдельный каталог: `tar xzf archive --wildcards '*/conversations/*' '*/projects/*'` (~16M), далее тот же `rg`. Нужно только право чтения архива (пункт 5 раздела 9).
- **Правило выдачи.** Каждый результат обязан нести `conversation_id` + путь события + дату, иначе это пересказ без доказательства — как в M3, где документ был источником актуальности.

## Ф4. Процедура для владельца — один блок, sudo, без изменения системы

Ничего не настраивает и не удаляет: только чтение архива, распаковка **одного** файла в защищённый временный каталог `0700` в `/var/tmp`, три хеша и удаление каталога. Ни один рабочий файл не перезаписывается.

```bash
sudo bash -s <<'M4'
set -u
A=$(ls -1t /mnt/amnesia-backup/openhands-agent/daily/openhands_*.tar.gz | head -1); echo "archive : $A"
L=$(tar tzf "$A") || { echo "FAIL: архив повреждён"; exit 3; }; echo "entries : $(printf '%s\n' "$L" | wc -l)  (tar tzf OK)"
M=$(printf '%s\n' "$L" | grep -F 'deployment/README.md' || true)
[ "$(printf '%s\n' "$M" | grep -c .)" -eq 1 ] || { echo "FAIL: запись отсутствует или неоднозначна — ничего не извлечено"; exit 2; }
echo "member  : $M"
umask 077; T=$(mktemp -d /var/tmp/m4-verify.XXXXXX) || exit 4
echo "record  : $(tar xzOf "$A" -- "$M" | sha256sum | cut -d' ' -f1)"
tar xzf "$A" -C "$T" -- "$M" || { rm -rf "$T"; echo "FAIL: извлечение не удалось"; exit 5; }
echo "extract : $(sha256sum "$T/$M" | cut -d' ' -f1)"
echo "live    : $(sha256sum /srv/openhands-agent/deployment/README.md | cut -d' ' -f1)"
rm -rf "$T"; echo "temp removed: $T"
M4
```

**Как читать результат.** Три строки `record`, `extract`, `live` должны быть одинаковыми, все равные `773e56f3e3bbba35640911c458027877289ffa3e525ecf7cbcb0250d11321ea6`:

- `record` = `extract` → архив целостен и tar.gz распаковывается корректно (**обязательное условие PASS**);
- `extract` = `live` → содержимое в архиве не искажено с 26.07 (**дополнительное**, допустимо расхождение, если файл правился после даты архива — здесь mtime 26.07 07:36 старше архива, поэтому расхождения быть не должно);
- `entries` > 0 и код выхода 0 → архив читается.

Любой иной исход — `FAIL` с указанием кода выхода (2 — нет записи, 3 — архив повреждён, 5 — извлечение не удалось). Пароли, токены и содержимое личных файлов при этом не выводятся: печатаются только имя записи и хеши.

Альтернатива без sudo, если владелец предпочитает не запускать скрипт: разово выдать чтение только на один файл — `sudo setfacl -m u:igor:rx /mnt/amnesia-backup/openhands-agent /mnt/amnesia-backup/openhands-agent/daily` и `sudo setfacl -m u:igor:r …/daily/openhands_2026-10-31.tar.gz`, выполнить проверку от `igor`, затем `sudo setfacl -b …` для снятия. Это тоже изменение прав, поэтому предложено, но **не выполнено**.

## Ф6. Нерешённые риски (отдельно, не закрыты этой проверкой)

Защита — только права `0700 root:root`; при копировании диска, смене владельца или выдаче доступа (в том числе по варианту с ACL выше) она исчезает. **Риск принят, но не устранён.**
2. **Копирование активных SQLite/Qdrant.** `Wants`/`After` не останавливают контейнер, `ProtectSystem=no`; `store/qdrant_db`, `store/history.db`, `automation/automations.db` снимаются на живой записи без `sqlite3 .backup` и без checkpoint WAL. 3. **Ограниченная ротация.** Реально ≈ две недели: 7 daily + недельные, удаляемые раньше задокументированных 28 дней (25.08, 20.10, 27.10). Архивы полные, не инкрементальные, поэтому удаление daily теряет весь день целиком; промежуточных версий между двумя живыми копиями нет. Старейшая живая копия — W42 от 18.10; переписка июля–сентября уже вне архива. **Риск не устранён; 7+4 копии не являются бессрочным архивом.**
4. **Отсутствие независимой второй копии.** Единственный носитель `/dev/sdb1` (`AMNESIA_BACKUP`), offsite-копии нет. Отказ диска, повреждение ФС или кража уничтожают всю историю; проверка восстановления при этом тоже станет невозможной. **Риск не устранён и не может быть закрыт на одном диске.**
