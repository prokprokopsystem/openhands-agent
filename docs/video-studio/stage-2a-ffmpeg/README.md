# Этап 2а — изолированная среда FFmpeg / ffprobe

Развёрнуто на mini-server в `/home/igor/video-studio`. Рендер не входит в этот
каталог: здесь только среда и правила её безопасного использования.

## Состав

| Файл | Назначение |
|---|---|
| `Dockerfile`, `guard.sh` | образ `video-studio/ffmpeg:8.0.1`; `guard.sh` становится entrypoint и проверяет tmpfs перед запуском ffmpeg |
| `compose.yaml` | изоляция, лимиты, tmpfs `/out`, вход `/work` только на чтение |
| `scripts/run-render.sh` | единственный разрешённый способ запуска и публикации результата |
| `scripts/verify.sh` | 25 автоматических проверок установки |

## Схема защиты диска

```
ffmpeg --> tmpfs /out (1 GiB, предел ядра) --> tar-поток --> ./out (диск хоста)
```

1. Каталог хоста **не смонтирован** в контейнер. У процесса монтажа нет цели для
   записи на диск — ни в `/srv`, ни в Paperless, ни в Nextcloud.
2. Всё, что создаёт ffmpeg, попадает в `tmpfs /out` размером 1 GiB. Предел
   задаёт ядро: при переполнении запись прекращается, файл остаётся усечённым.
3. Дополнительно действует `RLIMIT_FSIZE` = 1 GiB на один файл.
4. Публикация — поток `tar` из `tmpfs` в `./out`. Объём копии ограничен
   содержимым `tmpfs`, то есть теми же 1 GiB.
5. `run-render.sh` дополнительно отказывается работать, если на разделе меньше
   60 GiB свободно или `out/` уже занят более 15 GiB.

**Честная граница:** пункты 2 и 3 — жёсткие пределы ядра. Пункты 4 и 5 —
контролируемые проверки, а не квота файловой системы. Настоящей квоты на `out/`
нет: она требует прав root на хосте. Оператор с доступом к Docker может обойти
любую проверку — это свойство доступа, а не дефект конфигурации.

## Запуск

```bash
cd /home/igor/video-studio

# входные файлы кладутся в work/ (монтируется только на чтение)
./scripts/run-render.sh -i /work/in.mp4 -c:v libx264 -preset veryfast /out/out.mp4
```

Скрипт сам поднимает рабочий контейнер, выполняет ffmpeg, проверяет объём,
публикует результат в `out/` и останавливает контейнер. Временные файлы в
`tmpfs` исчезают вместе с контейнером.

Проверка установки:

```bash
./scripts/verify.sh
```

## Остановка и полное удаление

```bash
cd /home/igor/video-studio
docker compose down                 # остановить среду, образ остаётся
docker compose down --rmi local     # остановить и удалить образ
rm -rf /home/igor/video-studio      # удалить каталог
```

`docker compose down` не трогает образы, тома и сети других проектов.
Общий `docker prune` не нужен и не применяется.

## Технические особенности

- База `debian:bookworm-slim`, а не Alpine: бинарники BtbN собраны под glibc.
- `tmpfs /out` монтируется с режимом `1777`, потому что этот runtime не
  принимает `uid`/`gid` в опциях tmpfs. В контейнере один пользователь.
- Рабочий контейнер живёт постоянно (`sleep infinity`): tmpfs существует только
  пока контейнер запущен, поэтому рендеры выполняются в нём через `docker exec`.
- `docker cp` в этом runtime не видит `tmpfs` внутри контейнера, поэтому
  публикация идёт потоком `tar -cf -` из контейнера в `tar -xf -` на хосте.
- Лицензия GPL-2.0-or-later: вариант `gpl` включает `libx264` и `libx265`.
  Использование локальное; распространение образа требует соблюдения GPL.
