## Текущий производственный этап и следующий шаг

**Этап:** первый фильм «Маленькое добро» (также в творческих обсуждениях «Сон моей доброты»). **Пять видео доставлены на SSD, инвентаризация выполнена, вариант D утверждён, скрипт исправлен и проверен сухим прогоном. Рендер НЕ выполнялся и ждёт разрешения.** Близость названий не означает два разных текущих проекта.

1. **ВЫПОЛНЕНО:** инвентаризация пяти MP4, измерение LUFS, проверка декодирования, подготовка скрипта и монтажного плана — коммит `0dc0bc4`, Issue #12.
2. **УТВЕРЖДЕНО 21.11.2026:** просмотрены два контактных листа сцены 3. Варианты A/B/C обрезают лишь конец, оставляя «телескопическую» опору и две палки в середине. Рекомендован **D**: оставить только `6.833333–7.916667` (26 кадров, ~1.083 с), показывая уход робота и готовую крышу. По склейке со сценой 2 пропущенное действие является монтажной эллипсой; водопад с крыши остаётся недостатком. Подробности — [Issue #12](https://github.com/prokprokopsystem/openhands-agent/issues/12#issuecomment-7059063512).
3. **ИСПРАВЛЕНО:** `SCENE3_IN`/`S3_IN_FRAME` и `S3_FRAMES`, `xfade` 19 кадров и `acrossfade` на стыке 4→5, рамки 40 мс на прямых склейках, `-n` вместо `-y`, запись через `.part.mp4`, проверка существующего файла, нормализация timebase для `xfade`. Сухой прогон: 767 кадров, 31.958333 с. Тесты: 418 пройдено, 0 не пройдено. Отличие от плана: перетекание на прямых склейках сделано рамкой 40 мс, а не 0.4 с — настоящее перетекание укорачивает звук и расходится с видео на 1.2 с к концу фильма. Обоснование — в плане, раздел 6.
4. Пользователь и ChatGPT утверждают обрезку, переходы, звук и титр. **Реальный художественный рендер только после согласования и исправлений.**
5. OpenHands производит `MODE=disk` рендер через защищённый FFmpeg, проверяет `ffprobe` и звук, отдаёт MP4 для просмотра. После изменения в этом же задании обновляет именно этот файл в GitHub; не дублирует живой статус в README.

### Не делать автоматически

- Не форматировать, не перемонтировать и не перенастраивать SSD; **не трогать `/dev/sda` и `/dev/sdb` (`AMNESIA_BACKUP`)**.
- Не менять AMNESIA, Paperless, Nextcloud, OpenHands, общие Docker-настройки, не запускать `prune`.
- Не запускать тест 2 GiB/`--fill` на рабочем SSD; не устанавливать HyperFrames без отдельного задания.
- Не сливать PR #11 как побочный эффект «актуализации документов» без проверки самого кода и отдельного решения.
- Пока нет резервного копирования студийных материалов, **не удалять ни исходные MP4 на сервере, ни исходники на компьютере**.
- Не принимать старые записи UUID без чтения фактического `blkid`/`findmnt`, если UUID понадобится для операции: не использовать UUID по памяти или из старого текста как основание для привилегированных действий.

## Правило записи каждого изменения (обязательно)

После **любого** изменения сервера, кода, входных материалов, версии фильма или стадии работы:

1. Указать **что было → что стало**; конкретную дату, способ проверки, ссылку на отчёт/PR/коммит.
2. Отдельно указать: **ИЗМЕНЕНО / НЕ ИЗМЕНЕНО / ПРОЙДЕНО / НЕ ПРОВЕРЕНО / СЛЕДУЮЩЕЕ ДЕЙСТВИЕ**. План и догадку никогда не помечать «ПРОЙДЕНО».
3. Обновить именно этот файл (и профильную техническую инструкцию, если поменялась), **не копировать длинные блоки текущего статуса в README и глобальный `docs/Состояние.md`**.
4. При работе в ветке PR обеспечить, что этот файл на `main` остаётся актуальным. Если невозможно безопасно синхронизировать, явно указать **расхождение и конкретную ветку**; не маскировать его.
5. В следующем чате начинать с этого файла, затем только с актуальных задачи/кода; старые отчёты читать ради истории и доказательств.
