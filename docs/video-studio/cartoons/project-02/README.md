# Project 02 — новый короткий AI-мультфильм

**Статус:** подготовка; сюжет, персонажи и название ещё не утверждены. Создано по решению владельца 22.11.2026.

## Цель
Научиться регулярно создавать короткие, понятные и смешные мультфильмы для TikTok/Shorts, постепенно улучшая качество и набирая аудиторию. **Продажи и монетизация не являются текущей целью.**

## Инструменты и роли
- **Google Flow:** единственный основной генератор видео на данном этапе; используем доступные владельцу бесплатные ежедневные кредиты (ориентир — 50; фактический баланс проверяется в интерфейсе). Не покупать подписки без решения владельца.
- **Владелец + ChatGPT:** идея, художественные решения, эталонные изображения, конкретные задачи генерации, приёмка отснятых материалов.
- **GitHub:** документация, карточки, промпты, принятые решения, журнал попыток, задания агенту.
- **OpenHands + FFmpeg на mini-server:** только после передачи готовых материалов — технический монтаж, проверка звука/видео, подготовка финального MP4. Агент не подменяет собой режиссёра.
- **MP4, фото и прочие большие исходники:** хранить на mini-server, не в GitHub; в карточках — относительные пути / идентификаторы, без секретных данных.

## Порядок работы
1. Исследовать короткие юмористические форматы; вместе выбрать одну простую идею. Не утверждать сценарий автоматически.
2. Зафиксировать персонажа и окружение: детали, которые нельзя менять. Сохранить **эталонные кадры**, но не выдавать их наличие за гарантию постоянства.
3. Разбить утверждённую историю на несколько **карточек сцен** по шаблону `СЦЕНА-ШАБЛОН.md`.
4. Перед каждой генерацией проверить доступные функции Flow, стоимость в кредитах, входные изображения, конкретное действие и риск ошибок. Сначала использовать возможности интерфейса, затем расходовать кредиты.
5. Для каждой попытки записывать модель, режим, входные данные, промпт, затраты и обнаруженные изменения персонажа / объектов. Нельзя бесконечно перегенерировать: дневной бюджет ограничен.
6. Принятый фрагмент сохранять вместе с карточкой. Если ошибка существенная — обсуждать изменение постановки или технологии, а не автоматически тратить новые кредиты.
7. Когда приняты необходимые сцены, передать отдельное точное задание OpenHands: собрать черновик, проверить длительность и стыки, затем дать владельцу посмотреть. Не считать успешный кодек доказательством художественного качества.
8. После публикации — зафиксировать просмотры, удержание (если доступно), комментарии и практические выводы.

## Основные ограничения
- Генератор может менять очки, полоски, сумку, мелкие предметы, конструкцию окружения — даже при продолжении с последнего кадра. Это проблема модели, а не просто плохого промпта.
- При 50 кредитах в день выбирать короткие сцены и простые действия; заранее оценивать цену одной попытки.
- Не переключаться между генераторами внутри одного мультфильма без отдельного осознанного решения.
- Не изменять старые фильмы, исходники и окружение mini-server без отдельного поручения.
- Для начала предпочтительны короткие визуальные шутки, небольшое число персонажей, одна локация и понятная кульминация.

## Файлы
- `СЦЕНА-ШАБЛОН.md` — копировать для каждой утверждённой сцены, например `scene-01.md`.
- `ИДЕИ-И-ТРЕНДЫ.md` — исследование и необязательные идеи; **не сценарий**.

## Ближайший шаг
Обсудить и утвердить одну идею. До этого **не генерировать видео и не выдавать агенту задание на монтаж**.
