# Отчёт: исправления по блокирующему разбору PR #11

Дата: 15 ноября 2026. Ветка `video-studio-disk-storage`, база `a641da9`.
Ссылка: Issue #10, PR #11.

Работа велась только с кодом в рабочем каталоге. Привилегированные операции не
выполнялись: нет `mkfs`, `sgdisk`, `mount`, нет записи в `/etc/fstab`, нет
пересборки образа и запуска контейнеров. AMNESIA, Paperless, Nextcloud и
рабочая конфигурация OpenHands не затрагивались.

## Что было не так

### 1. Двойное выполнение в установочных скриптах

`host/setup-storage.sh` содержал функцию `run()`, которая при `--apply`
исполняла команды уже в секции «План». Затем шла секция «Применение», которая
повторяла `fallocate` и `mkfs.ext4`. При этом `mount` вызывался до записи строки
в `fstab`, а обработчик ошибки не учитывал, что файловая система может быть уже
смонтирована.

### 2. Разный допуск на хосте и в контейнере

`guard.sh` сверял размер с маркером с абсолютным допуском 1 GiB, а
`scripts/verify-storage.sh` — с ±5%. На объёме 927 GiB это 46 GiB, поэтому
корневой раздел 935 GiB проходил проверку как «наше хранилище».

### 3. `--fill` на рабочем диске

`scripts/verify-storage.sh --fill` писал до `ENOSPC`. На рабочем SSD это до
927 GiB записи: износ и полное занятие места.

### 4. Разрушительные ветки в тестах

Проверка `--apply` запускалась на реальном устройстве. Даже без root это
попытка `sgdisk --zap-all`.

### 5. Переопределение путей через окружение

`DEV`, `MOUNT`, `IMAGE`, `FSTAB` читались из окружения: под root это позволяло
направить `mkfs` или `umount` на произвольный объект. `--reformat` принимался.

## Что изменено

### Один проход вместо двух

Все четыре привилегированных скрипта (`setup-storage.sh`,
`setup-ssd-storage.sh`, `remove-storage.sh`, `resize-storage.sh`) устроены
одинаково:

```bash
stage() {                    # единственная точка исполнения
  local desc="$1" fn="$2"
  if [ "$APPLY" = "1" ]; then printf '+ %s\n' "$desc"; "$fn"
  else printf '  %s\n' "$desc"; fi
}

stage "fallocate ..." do_image
stage "mkfs.ext4 ..." do_mkfs
stage "добавить строку в fstab ..." do_fstab
stage "mount ..." do_mount
```

В примере `stage` только печатает. Секции «Применение» больше нет, поэтому
повторного `fallocate` и `mkfs` не бывает по построению, а не по договорённости.

### Порядок шагов

`образ → mkfs → fstab (копия, findmnt --verify, проверка после записи) → mount →
каталоги → маркер → сверка размера`. Строка `fstab` пишется до `mount`, как и
требовалось.

### Откат на любом выходе

Ловушка переведена с `ERR` на `EXIT`. Причина: ошибка в условии вида
`mount "$MOUNT" || die` в `ERR` не попадает, и откат не срабатывал — это
воспроизведено тестом S10 до исправления. Теперь откат видит и `die`, и
необработанную ошибку `set -e`.

Правила отката:
- `fstab` восстанавливается побайтно из копии;
- живой образ не удаляется: сначала `umount`, и только если размонтирование
  удалось — `rm`;
- раздел диска не стирается никогда, скрипт печатает фактическое состояние и
  ручной путь разбора.

### Один модуль сверки размера

Новый `size-check.sh` — POSIX-модуль с `size_matches(total_ki, declared_gib)` и
допуском 1 GiB. Его используют `guard.sh` (образ), `scripts/verify-storage.sh`
(хост) и установочные скрипты. `Dockerfile` копирует модуль в
`/usr/local/bin/size-check.sh`.

### `--fill` только на тестовом хранилище

Проверки идут до запуска контейнера и до любой записи:

1. `MOUNT` не равен `/srv/video-studio-data`;
2. серийный номер источника не `24257G400264`;
3. размер не больше 16 GiB;
4. в хранилище лежит файл `.fill-test-ok`, созданный человеком.

Любое нарушение — код 2 и объяснение, как сделать тестовое хранилище.

### Пути — константы

`MOUNT`, `IMAGE`, `DEV`, `FSTAB`, `PROJECT_DIR` объявлены через `readonly`.
Подмена через окружение не работает (тесты L4, S6). `--reformat` не принимается:
неизвестный аргумент, код 2 (тест S7).

## Как проверено

`tests/run-tests.sh` — стенд без реального диска. Он подменяет `lsblk`,
`findmnt`, `mkfs.ext4`, `sgdisk`, `mount`, `umount`, `df`, `systemd-analyze`,
`docker`; всё выполняется в `mktemp -d`, привилегии не нужны.

```bash
cd docs/video-studio/stage-2a-ffmpeg
./tests/run-tests.sh
```

## Что не проверено и почему

- Пересборка образа и `scripts/verify.sh` внутри контейнера. Образ
  `video-studio/ffmpeg:8.0.1` собран до появления `size-check.sh`, поэтому
  `guard.sh` в нём пока не найдёт модуль и вернёт код 78. Нужна пересборка:
  это изменение образа, а не только файлов репозитория.
- Проверки в контейнере требуют `docker compose run`, то есть запуска
  контейнера. В этом проходе запрещено.

Порядок после разрешения:

```bash
cd /home/igor/video-studio
docker compose build studio            # подхватит size-check.sh
./scripts/verify.sh                    # ожидается 25 ПРОЙДЕНО, 0 НЕ ПРОЙДЕНО
./scripts/verify-storage.sh            # хранилище ещё не создано: будет отказ, это норма
```

`./scripts/verify-storage.sh --fill` на рабочем SSD не запускать: скрипт теперь
отклоняет его сам, но запускать его там не нужно.
