## 1. Аудит механизмов secrets Agent Canvas 1.6.1

### 1.1. Штатные механизмы

| Механизм | API | Где хранится | Доступен агенту? |
|----------|-----|-------------|-----------------|
| Settings secrets | `GET/PUT /api/settings/secrets`, `GET/DELETE /api/settings/secrets/{name}` | `config/settings.json` (внутри `misc_settings` или рядом) | ⚠️ Да — `settings.json` лежит в `/home/openhands/.openhands/` (режим 600, владелец 10001), агент читает его через `terminal` |
| Conversation secrets | `POST /api/conversations/{id}/secrets` | В памяти беседы | ⚠️ Да — агент в этой беседе видит переданные секреты |
| Agent context secrets | `agent_context.secrets` в settings | `config/settings.json` | ⚠️ Да — та же проблема |
| Env-файл хоста | `env_file` в compose | `/srv/openhands-agent/secrets/.env` (igor:igor, 600) | ❌ Нет — каталог `secrets/` не смонтирован в контейнер |
| LLM profiles | `config/profiles/*.json` | Bind mount → `/home/openhands/.openhands/profiles/` | ⚠️ Да — владелец 10001, режим 600, `terminal` читает |

### 1.2. Фактический доступ агента к secrets

| Ресурс | Владелец | Права | Доступ через terminal | Содержит |
|--------|----------|-------|----------------------|----------|
| `profiles/deepseek-chat.json` | 10001:10001 | 600 | ✅ Читает | DeepSeek API-ключ |
| `profiles/claude.json` | 10001:10001 | 600 | ✅ Читает | Claude API-ключ |
| `agent-canvas/secret-key.txt` | 10001:10001 | 600 | ✅ Читает | Внутренний ключ Canvas |
| `settings.json` | 10001:10001 | 600 | ✅ Читает | Конфигурация |
| `/srv/.../secrets/.env` | igor:igor | 600 | ❌ Не видит | `LOCAL_BACKEND_API_KEY` |
| `/var/run/docker.sock` | — | — | ❌ Не существует | — |

### 1.3. Вывод

**Все штатные механизмы secrets Canvas хранят данные в файлах, доступных агенту через `terminal` и `read_file`.** Единственное безопасное место — `/srv/openhands-agent/secrets/` на хосте, не смонтированное в контейнер. Но оно не видно агенту — данные нужно передавать через env_file или отдельный сервис.

## 2. Модель хранения учётных данных

### 2.1. Принципы

| Принцип | Реализация |
|---------|-----------|
| Не в Git | Все credentials — в `.gitignore`, только `.example`-файлы в репозитории |
| Не в `/projects` | Рабочий каталог — RW для агента, неприемлемо |
| Не в `profiles/*.json` | Агент читает — неприемлемо для integration credentials |
| Не в `/docs` | Read-only bind mount, не для секретов |
| Отдельный секрет на интеграцию | Каждый токен/ключ — отдельная переменная/файл |
| Минимальные права | Read-only где возможно, scope-ограниченные токены |
| Ротация и отзыв | Возможность отозвать токен без перестройки всей системы |
| Резервная копия | Только в зашифрованном виде (`gpg` или `age`) |
| Отключение интеграции | Удаление токена + откат конфигурации |

### 2.2. Место хранения

**Выбрано:** `/srv/openhands-agent/secrets/` на хосте mini-server.

| Свойство | Значение |
|----------|---------|
| Владелец | `igor:igor` |
| Права каталога | 700 |
| Права файлов | 600 |
| Смонтирован в контейнер? | ❌ Нет |
| Доступен агенту? | ❌ Нет |
| Доступен через `env_file` в compose? | ✅ Да — переменные окружения |
| Резервная копия | `tar czf - secrets/ \| gpg -c > backup-secrets-YYYY-MM-DD.tar.gz.gpg` |

### 2.3. Передача credentials сервисам

**Вариант A — env_file (для контейнера агента):**
- Плюс: просто, уже используется для `LOCAL_BACKEND_API_KEY`
- Минус: переменные окружения видны процессу агента → агент может прочитать через `env`

**Вариант B — отдельный gateway-сервис (для Telegram):**
- Плюс: токен вообще не попадает в контейнер агента
- Минус: нужен отдельный контейнер/процесс
- Агент общается с gateway через HTTP (без токена)

**Выбор:** для интеграций внутри контейнера — env_file. Для Telegram — отдельный gateway.

## 3. Анализ Telegram-интеграции

### 3.1. Поддерживает ли Canvas Telegram напрямую?

**Нет.** Agent Canvas 1.6.1 не имеет встроенного Telegram-провайдера. Нужен внешний gateway/bridge.

### 3.2. Возможен ли long polling без публичного HTTPS?

**Да.** Telegram Bot API поддерживает `getUpdates` через long polling. Не требует webhook → не требует публичного HTTPS. Можно работать внутри WireGuard.

### 3.3. Ограничение одним Telegram ID

Telegram Bot API передаёт `message.from.id` в каждом сообщении. Gateway проверяет `chat_id == <разрешённый ID>` и игнорирует остальные. Техническая защита на уровне gateway, не зависящая от prompt агента.

### 3.4. Архитектура Telegram-гейта

```
Telegram API (облако)
    ↕ long polling (getUpdates)
Telegram Gateway (отдельный процесс/контейнер на mini-server)
    ├─ Токен бота (в secrets/, НЕ в контейнере агента)
    ├─ Фильтр: только chat_id Игоря
    ├─ Форвардинг: сообщение → Agent Canvas API
    └─ Ответ: Agent Canvas → sendMessage
    ↕ HTTP (WireGuard, 10.77.0.2:8000)
Agent Canvas (контейнер openhands-agent)
```

### 3.5. Риски

| Риск | Мitigation |
|------|-----------|
| Токен бота скомпрометирован | Отозвать через @BotFather, сгенерировать новый |
| Спуфинг chat_id | Telegram гарантирует подлинность from.id |
| DDoS через бота | Ограничение одним chat_id |
| Gateway падает | Systemd-сервис с авторестартом |

## 4. Разделение Этапа 5

### 5A — Поддержка со стороны хозяина (read-only мониторинг)

- Проверка доступности Canvas
- Проверка healthcheck
- Уведомление при сбое (через Telegram, после 5C)

### 5B — Healthcheck и мониторинг

- Существующий docker healthcheck (уже работает)
- `systemctl status` — мониторинг
- **Новый сервис мониторинга пока не добавляется**

### 5C — Текстовый Telegram-бот через long polling

- Новый бот (не AMNESIA-бот)
- Только chat_id Игоря
- Текст → Agent Canvas → ответ → Telegram
- Long polling, без HTTPS
- Gateway снаружи контейнера агента

### 5D — Голосовые сообщения через Telegram

- Приём голосового сообщения → распознавание речи → текст → Agent Canvas
- Ответ текстом или синтезом речи
- Выбор способа распознавания речи — отдельное решение

### 5E — Ручное обновление и откат

- Обновление: `docker pull` нового digest → обновить compose → `systemctl restart`
- Откат: вернуть старый digest в compose → `systemctl restart`
- **Версия образа фиксируется digest**, автообновление выключено

### Публичный домен и HTTPS

- ❌ Не открывается
- Canvas остаётся WG-only
- Вынесен в отдельный необязательный этап
