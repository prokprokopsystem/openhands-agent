# OpenHands Agent — План

**Версия:** 1.0 (25 июля 2026)  
**Единая нумерация этапов.** Все документы ссылаются на эту нумерацию.

---

## Этап 0 — Инвентаризация ✅

- Read-only проверка mini-server (CPU, RAM, диск, Docker, сеть, порты)
- Карта ресурсов
- Вывод: готов к установке

## Этап 1 — Исследование платформы ✅

- Выбор: Agent Canvas v1.6.1 (старый Local GUI deprecated)
- Проверка образа через GHCR manifest (архитектура, пользователь, порты, volumes)
- Вывод: подходит, Docker-режим, без docker.sock

## Этап 2 — Дизайн развёртывания ✅

- compose.yaml с фиксированным digest, healthcheck, изоляцией
- Скрипты: prepare, start, stop, status, logs, purge-test
- Systemd unit
- Egress-политика (правила, проверка)
- Вывод: готов к тестовому запуску

## Этап 3 — Первый тестовый запуск (следующий)

**Только с пустым test-workspace. Без GitHub, SSH, n8n, Nextcloud, Notion.**

- Выполнить prepare.sh на mini-server
- Запустить контейнер
- Проверить WebUI (текст, файлы, фото)
- Проверить авторизацию
- Проверить остановку/перезапуск
- Проверить egress-изоляцию
- Замерить CPU/RAM
- Остановить, зафиксировать результат

## Этап 4 — GitHub (read-only)

- Подключить один тестовый репозиторий
- Read-only: клонирование, чтение, diff
- Запрет push в main

## Этап 5 — Шлюз разрешений

- Независимый слой подтверждения операций
- Push, SSH, n8n, удаление — только через шлюз
- Не привязан к OpenHands

## Этап 6 — n8n

- Изучение workflow (read-only)
- Создание черновиков отдельно от production

## Этап 7 — Nextcloud и Notion

- Доступ к отдельным каталогам/базам
- Чтение → создание → изменение с подтверждением

## Этап 8 — SSH и Docker

- Отдельный пользователь агента
- Wrapper и белый список команд

## Этап 9 — Эксплуатация

- Голос, Telegram, HTTPS, домен
- Мониторинг, backup, обновление
