## Режимы проекта

- **TEST MODE** — текущая жёсткая изоляция, пустой `test-workspace`, без доступа к внутренним интеграциям.
- **WORK MODE** — тот же Agent Canvas, systemd, supervisor и контейнер, дополненные отдельным постоянным профилем разрешений и инструментов.

Переход в WORK MODE не требует переписывания базового deployment. Рабочие полномочия подключаются отдельной конфигурацией после успешного тестового запуска.

### 5D — Голосовые сообщения через Telegram 🔲

**Цель:** приём голосового сообщения из Telegram → распознавание речи (STT) → передача текста агенту.

**Порядок работ:**

1. Выбрать вариант STT: локальный движок (whisper.cpp, faster-whisper) или внешний API (OpenAI Whisper API, DeepSeek audio)
2. Определить необходимые инструменты и права: доступ к хосту, Docker, Telegram-файлам, egress (если внешний API)
3. Подготовить изменения в репозитории: архитектура gateway, зависимости, конфигурация
4. Проверить резервную настройку и возможность отката
5. Применить изменения на мини-сервере
6. Проверить получение голосового сообщения из Telegram
7. Проверить скачивание файла
8. Проверить распознавание (STT)
9. Проверить передачу распознанного текста агенту
10. Провести пользовательскую проверку
11. Обновить документацию после подтверждения результата

**Агенту для 5D не предоставлены:**
- контролируемый доступ к хосту мини-сервера;
- разрешённые команды для Docker/systemd и журналов;
- доступ к Telegram-файлам (Bot API getFile);
- STT-движок либо разрешённый внешний STT API;
- egress-доступ к внешнему STT API (если выбран внешний).
