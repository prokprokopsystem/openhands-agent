# OpenHands Agent — План

**Актуализирован:** 24 октября 2026.
**Текущая работа:** восстановление простого агента вместо расширения broker. Прежний план 4D отменён в части внедрения broker/connector решением пользователя 11 октября. История прежнего плана доступна в Git.

## Критерий результата

Пользователь ставит простую задачу через Canvas или Telegram, агент выполняет её через DeepSeek. Сохраняются веб-доступ и существующий автозапуск. AMNESIA, Nextcloud и другие контейнеры не затрагиваются. Новый broker, wrapper или параллельная инфраструктура не добавляются.

## Шаги

1. **Частично выполнено:** отключить connector и удалить broker. Известные рабочие компоненты удалены 11 октября; остатки и Git deployment ещё требуют согласования.
2. **Выполнено:** default → deepseek-chat подтверждено live API; DeepSeek Flash штатно активирован через POST /api/profiles/deepseek-chat/activate (llm_applied=true). После этого OpenHands выполнил проверки подключений.
3. **Частично выполнено:** ответ DeepSeek и создание/чтение файла через Canvas подтверждены 24 октября; Telegram ещё не проверен.
4. **Не выполнено:** проверить сохранение автозапуска по конфигурации служб; не перезагружать весь сервер ради проверки.
5. **Не выполнено:** сократить действующие правила после просмотра активного профиля. Не расширять полномочия на другие сервисы.
6. **Не выполнено:** удалить ненужные остатки broker, согласовать фактические deployment/config-шаблоны без секретов и документацию. Не создавать дополнительные копии; не удалять посторонние данные и архивы.

## Новое направление — долговременная память (31 октября 2026)

По решению пользователя стартует отдельная последовательность M0–M4: зафиксировать план в Git → точечная read-only проверка ресурсов/внешнего архива → изолированный прототип Mem0 или более простой проверенной альтернативы → интеграция с новыми событиями Canvas и поиском → архивирование и тест восстановимости. Текущий эксплуатационный план и DEC-023 не отменяются. **Сейчас только документация M0; работающий агент не менялся.** Подробности: [Память-пилот-2026-10-31.md](Память-пилот-2026-10-31.md).


**M1 (31.10): выполнено по read-only отчёту агента.** Ресурсы достаточны, внешний архив/таймер обнаружены. **M2: следующий шаг** — отдельный пилот Mem0 OSS + fastembed + embedded Qdrant, без изменения Canvas и остальных контейнеров. Тесты: два проекта, точный и смысловой поиск, версионность и источники, замеры ресурсов. Детали: [Память-M1-2026-10-31.md](Память-M1-2026-10-31.md). Не создавать дублирующий архивный tar: общий бэкап уже содержит рабочую папку OpenHands; долгосрочную ретенцию решить позже.


**M2 (31.10): выполнен, 8 из 8 проверок PASS.** Прототип `/projects/memory-pilot` собран как библиотека: Mem0 OSS 2.2.1 + fastembed 0.9.1 + embedded Qdrant, телеметрия выключена, LLM не вызывается (`infer=False`). Корпус 28 записей из двух проектов, источники проверяемы. Замерено: 738 МБ RAM в пике, 543 МБ диска, поиск 46 мс по медиане, холодный старт 1.5 с. Подробности: [Память-M2-2026-10-31.md](Память-M2-2026-10-31.md).

**M3: следующий шаг, требует решения.** Блокирующее ограничение: embedded Qdrant держит эксклюзивную блокировку каталога на всё время жизни процесса, `close()` её не освобождает — два процесса одновременно store не откроют. До начала M3 выбрать: единственный процесс-владелец хранилища с очередью запросов либо иной режим хранения. Также на M3: автозагрузка контекста в новый чат, автоматическое извлечение фактов (нужен `infer=True` и DeepSeek), очередь с checkpoint при сбоях. **Автоматической памяти в чатах пока нет.**
