### 4D — Постоянные управляемые инструменты агента 🔄

Канонический документ проекта 4D:

`docs/План Этапа 4D — Архитектура broker.md`

**Статус:** 4D.0 REVIEW PASS; 4D.1 реализован и получил REVIEW PASS repository-only. Broker ещё не установлен и не активирован на сервере; 4D.2 требует отдельного точного разрешения.

#### Неподвижные принципы

- broker — отдельный слой и не владеет base Canvas lifecycle;
- fixed adapters вместо registry shell commands;
- request protocol: bounded JSON через stdin; request params через `SSH_ORIGINAL_COMMAND` запрещены;
- broker core не читает target credentials;
- credential-bearing adapters имеют отдельные Unix identities/secret boundaries;
- Level A — read-only;
- Level B — только project-scoped reversible writes;
- по DEC-022 **любые systemctl mutations остаются Level C**;
- Level C — только trusted root-owned one-time approval с atomic consume+execute без grant через broker core; до реализации disabled;
- 4D.2 и 4D.4 до approval subsystem являются operator-mediated Level C bootstrap и требуют отдельного точного разрешения пользователя вне Canvas/broker;
- Canvas Connector принимается отдельно и после него обязательно фиксируется новый canonical recovery baseline.

#### Этапы реализации 4D

- **4D.0 ✅** — architecture v2.2, review PASS.
- **4D.1 ✅ REVIEW PASS** — Broker Core v2 repository-only: wire protocol, schema/canonicalization, modular registry, dispatcher, fixed adapter interface, audit, B/C disabled до 4D.6/4D.8; 35/35 unit/negative tests и local process-path PASS.
- **4D.2 🟡** — exact frozen-v1 → v2 migration package, per-adapter isolation, preserved broker client key/restricted authorized_keys/pinned host trust, rollback/validation подготовлены локально; operator-mediated server preflight/application ещё не выполнены.
- **4D.3 🔲** — реализация mini-server Level A adapter/tools + host-only acceptance; это ещё не Canvas end-to-end.
- **4D.4 🔲** — Canvas Connector + connector rollback + новый canonical base+connector recovery SHA.
- **4D.5 🔲** — Canvas → broker Level A end-to-end acceptance.
- **4D.6 🔲** — Level B project-scoped writes; systemctl excluded.
- **4D.7 🔲** — service adapters: VPS → n8n → GitHub → Nextcloud → Notion → AMNESIA, каждый с отдельной identity/credential boundary.
- **4D.8 🔲** — trusted Level C creator + atomic consumer/executor, exact canonical request binding, TTL, single-use, symlink/race protection; grant через core отсутствует.
- **4D.9 🔲** — end-to-end acceptance и freeze 4D v1.

**Правило:** если исправление текущего подэтапа требует выйти за разрешённый scope — STOP и сначала изменение плана.
