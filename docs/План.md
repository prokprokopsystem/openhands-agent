#### Неподвижная граница 4D

Broker — отдельный слой. Он **не владеет и не устанавливает base Canvas deployment**.

`setup-broker` не имеет права заменять:
- compose;
- prepare/validate/runtime/watchdog/supervisor;
- Canvas systemd unit;
- Canvas network/firewall;
- Nginx;
- Canvas profiles/LLM/conversations;
- Telegram gateway;
- backup/WireGuard.

Допускается только отдельный одноразовый Canvas Connector: client key RO mount + pinned known_hosts RO mount + точный доступ `10.89.0.2 → 10.89.0.1:22`. Connector не является частью broker installer.

#### Финальная схема

```text
Canvas
  → local broker transport
  → policy/registry
  → fixed adapter
  → target
  → verify/rollback/audit
```

Canvas имеет один broker credential. Target credentials остаются host-side.

#### Risk model

- **A** — read-only, автоматически.
- **B** — project-scoped обратимые изменения, автоматически при наличии pre-check/verify/rollback или доказанной идемпотентности.
- **C** — только one-time approval после явной команды пользователя; без approval технически заблокирован.

#### Этапы реализации 4D

- **4D.0 ✅** — финальная архитектура и границы.
- **4D.1 🔄** — Broker Core v2, repository-only. Старый broker используется только как исходный материал. Modular registry, adapters, strict validation, audit, no `bash -c` registry execution. Base deployment не меняется.
- **4D.2 🔲** — Host installation v2: broker user, forced SSH, broker files, narrow helpers/sudoers. Installer не касается Canvas base.
- **4D.3 🔲** — Mini-server Level A read-only tools.
- **4D.4 🔲** — отдельный одноразовый Canvas Connector и freeze connector.
- **4D.5 🔲** — Mini-server Level B project-scoped tools.
- **4D.6 🔲** — adapters: VPS → n8n → GitHub → Nextcloud → Notion → AMNESIA.
- **4D.7 🔲** — Level C one-time approval capability.
- **4D.8 🔲** — end-to-end acceptance и freeze 4D v1.

**Правило:** если для исправления текущего подэтапа требуется выйти за разрешённый scope файлов — STOP и сначала изменить план.
