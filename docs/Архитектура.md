# OpenHands Agent — Архитектура

**Принцип:** модульная система. OpenHands/Agent Canvas — инженерное ядро, но интерфейс, интеграции, модели и разрешения не привязаны к одному компоненту навсегда.

---

## Компоненты

```
Пользовательские устройства (ПК, телефон)
  │
  ├─ WireGuard (тест) / HTTPS (будущее)
  │
  ▼
Agent Canvas (ghcr.io/openhands/agent-canvas:1.6.1)
  ├─ WebUI :8000 (/canvas)
  ├─ Agent Server :18000 (internal)
  └─ Automation backend :18001 (internal)
       │
       ▼
  OpenHands Agent (default) или ACP-агенты (Codex, Claude Code, Gemini)
       │
       ▼
  Профиль режима
       ├─ TEST MODE
       │    ├─ /projects → пустой test-workspace
       │    ├─ жёсткая egress-изоляция
       │    └─ внутренние интеграции недоступны
       └─ WORK MODE (после успешного теста)
            ├─ тот же базовый deployment
            └─ отдельный постоянный профиль разрешений и инструментов
                 │
                 ▼
            Шлюз разрешений
                 ├─ GitHub (разрешённые операции)
                 ├─ n8n
                 ├─ Notion (разрешённые базы)
                 ├─ Nextcloud (выделенные папки)
                 └─ AMNESIA
```

## Границы

- **Agent Canvas** — WebUI + агент. Можно заменить на другой ACP-совместимый агент.
- **Базовый deployment** — Agent Canvas, systemd, supervisor и контейнер; одинаковая основа для TEST MODE и WORK MODE.
- **Профиль режима** — отдельная конфигурация разрешений и инструментов; переход в WORK MODE не требует переписывания базового deployment.
- **Шлюз разрешений** — независимый технический слой ограничения полномочий. Остаётся при замене ядра и не означает обязательное ручное подтверждение каждой операции.
- **Интеграции WORK MODE** — n8n, разрешённые базы Notion, выделенные папки Nextcloud, AMNESIA и разрешённые операции GitHub доступны постоянно в пределах рабочего профиля.
- **Инфраструктура** — VPS, mini-server, WireGuard, домены. Не изменяется агентом.

## Модель разрешений WORK MODE

- Обычные действия, явно разрешённые профилем, выполняются без ручного подтверждения каждого шага.
- Подтверждение обязательно только для массового удаления, production deployment, операций с `main`, ключами, firewall, `sudo` и system services.
- Шлюз применяет технические ограничения к ресурсам и операциям даже при отсутствии ручного подтверждения.
- WORK MODE реализуется отдельным ограниченным этапом только после успешного TEST MODE.

## Безопасность

- Docker socket не используется
- Отдельная сеть `10.89.0.0/28`
- TEST MODE: egress разрешает DNS и публичный интернет, блокируя internal, LAN, AMNESIA и Nextcloud
- `no-new-privileges:true`
- LLM-ключи в WebUI, хранятся в `/home/openhands/.openhands/` (config volume)
- `LOCAL_BACKEND_API_KEY` — авторизация, WG-only на тесте

## Заменяемость

1. Заменить Agent Canvas → другой ACP-агент: профиль и шлюз разрешений остаются.
2. Заменить LLM-провайдера → через WebUI, без перестройки.
3. Заменить mini-server → перенести volumes и compose.

## Не изменять

- Инфраструктуру AMNESIA (проект, контейнеры, каталоги) вне явно разрешённых операций профиля
- Nextcloud (AIO, данные)
- WireGuard (конфигурация, native unit)
- VPS (Nginx, n8n, домены, сертификаты)
- Системные пользователи и sudoers
