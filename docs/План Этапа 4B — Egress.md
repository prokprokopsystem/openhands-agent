## 1. Фактический сетевой доступ контейнера (сейчас)

### 1.1. Текущие правила iptables

```
Правило 1:  ESTABLISHED,RELATED → RETURN
Правила 2-8: DROP 127.0.0.0/8, 169.254/16, 10.0.0.0/8, 172.16/12, 192.168/16, 100.64/10, 95.217.239.148
Правила 9-10: DNS (UDP+TCP 53) → RETURN
Правило 11: HTTP/HTTPS (80, 443) → RETURN
Правило 12: DROP всё остальное
```

### 1.2. Результаты проверки

| Направление | Ресурс | Результат | Причина |
|-------------|--------|-----------|--------|
| DNS | Любой | ✅ Работает | Правило 9-10 |
| Публичный HTTPS | `*:443` (DeepSeek, GitHub, Google, любые сайты) | ✅ Доступен | Правило 11 |
| LAN | `192.168.100.1` | ❌ Заблокирован | Правило 6 |
| Docker-сети | `10.89.0.1`, `172.16.0.0/12` | ❌ Заблокирован | Правила 4, 5 |
| WireGuard | `10.77.0.2` | ❌ Заблокирован | Правило 4 |
| VPS | `95.217.239.148` | ❌ Заблокирован | Правило 8 |

### 1.3. Вывод

Текущий firewall **разрешает весь публичный исходящий HTTPS** (`*:443`) и DNS. LAN, WireGuard, Docker-сети, VPS и другие внутренние ресурсы заблокированы. Фильтрация — только по IP и портам, **не по доменам**.

## 2. Необходимый доступ для WORK MODE

WORK MODE требует публичный HTTPS для DeepSeek API и GitHub. Оба уже работают через правило 11 (`*:443`). Для чтения публичной документации также используется `*:443`.

**Никаких изменений egress не требуется.**

## 3. Технический анализ: доменное ограничение

### 3.1. Средствами iptables

Доменное ограничение напрямую средствами обычного `iptables` **не реализуется**. `iptables` работает на уровнях L3/L4 (IP-адреса, порты). Домены (L7) требуют HTTP-прокси.

### 3.2. Альтернативы

| Метод | Статус |
|-------|--------|
| iptables + ipset (IP-списки) | Хрупко: динамические адреса GitHub/CDN |
| HTTP-прокси (Squid) | **Сейчас не добавляем** — новый компонент, нарушает архитектурный принцип |
| DNS-фильтрация (dnsmasq) | Обходится прямым IP-запросом |
| Текущий подход (HTTPS всем, внутренние заблокированы) | ✅ Принят |

### 3.3. Решение

HTTP-прокси сейчас не добавляем. Оставляем текущую модель: публичный HTTPS разрешён, внутренние сети заблокированы на IP-уровне.
