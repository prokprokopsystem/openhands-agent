- Конденсация текущего контекста модели не удаляет первичные события на диске; это не архивирование.

## Цель
Локальная долговременная память с поиском по смыслу и по точным словам, по нескольким проектам, с проверяемыми ссылками на первоисточники, версиями/датами и актуальностью. Сохранять полную историю локально, выдавать DeepSeek только относящиеся к запросу фрагменты; избегать лишних вызовов дорогих моделей.

## Архитектурный кандидат, ещё не установленный
1. **Горячее хранилище на mini-server**: существующие Canvas events + отдельное локальное хранилище фактов/индекса. Путь и формат выбрать после read-only осмотра доступного места и вариантов интеграции.
2. **Mem0 OSS (кандидат)**: изолированный прототип, Python SDK, поиск и обновление воспоминаний. Сначала сравнить стоимость и реально доступные интеграции, векторную модель, базу, версию и зависимости; никаких OpenAI API-ключей по умолчанию. Проверить, поддерживается ли DeepSeek через совместимый интерфейс; эмбеддинги предпочтительно локальные при допустимой нагрузке. Рассмотреть встроенные простые альтернативы до установки дополнительных сервисов.
3. **GitHub**: по-прежнему только проверенные решения, код, инструкции, версии, ссылки на источники; не отправлять сырые разговоры, секреты и персональные сведения.
4. **Архив**: использовать существующую общую систему архивирования на внешнем диске, добавить логический раздел agent-memory. Физический путь, формат и механизм неизвестны до проверки. Не создавать второй независимый backup-сервис.

## Жизненный цикл данных
- Запись: первичное событие и исходный документ остаются неизменными; выделенные из них факты имеют source_id, проект/темы, timestamp, версию, статус актуальности и ссылку на источник. Новый факт не перезаписывает без следа старый.
- Поиск: сначала локальный индекс (гибрид точного + семантического поиска), затем при необходимости оригинал, другие проекты, GitHub или подключённый архив. Фрагменты с источниками и бюджетом токенов.
- Рост: измерять фактические объёмы диска, число событий, размер индекса и время поиска. Никакой автоматической удаления «по возрасту», пока не подтверждены восстановимость, контрольные суммы и поисковая доступность архива.
- Архивирование: согласованная инкрементальная копия на внешний диск, манифест, хеши, проверка восстановления. Отдельная запись статуса архива и указатель в локальном каталоге. Недоступность внешнего диска не должна блокировать основную работу; извлечение из холодного архива сообщает об отсутствии диска, а не выдумывает содержимое.
- Уплотнение: агрегировать старые производные индексные записи и устранять дубликаты только с сохранением ссылок на первоисточник. Сжатие исходных архивов возможно лишь без потерь; LLM-сводки не считаются заменой оригинала.
- Очистка: только после успешного восстановления тестовой архивной записи и подтверждения границ удаления. На этапе пилота **ничего автоматически не удалять**.
- Безопасность: секреты, приватные ключи, токены и личные документы не отправлять в GitHub или внешнюю LLM для индексирования без отдельного разрешения; исключить их на этапе прототипа.

## Поэтапная реализация и критерии приёмки
**Этап M0 (сейчас):** документировать решение в Git, не менять runtime. Подтвердить исходные данные по Git/аудиту.
**Этап M1:** read-only проверить версии, место и монтирования, уже существующий внешний архив, доступные ресурсы CPU/RAM, пути и настройки. Только конкретные необходимые факты, без повторного полного аудита.
**Этап M2:** изолированный локальный прототип на обезличенных, разрешённых для теста копиях документов Git (минимум два разных проекта), без подключения к Canvas. Проверить точный и смысловой поиск, межпроектную выдачу, исправление устаревшей информации, источник/дату и невысокую стоимость. Не поднимать новые сервисы, пока не согласованы реальные зависимости.
**Этап M3:** подключение к новой истории событий Canvas с проверкой, что записи не теряются, и извлечение результатов при старте и в ходе беседы. Сохранить raw events; модель получает только подборку.
**Этап M4:** интеграция с существующим архивом, тест восстановления и поиска в холодном архиве, мониторинг заполнения, только потом правила retention/очистки.

## Тесты, обязательные для каждого этапа
- Тест запоминания и восстановления в **новом разговоре**.
- Запрос через два разных проекта, включая точное имя файла/номер и семантическую формулировку.
- Исправление факта: старое решение помечается устаревшим; возвращается новое и причина изменения.
- Указание источника/даты; отсутствие ответа при отсутствии доказательств.
- Тест отказа внешнего диска и последующего восстановления данных.
- Сохранность после перезапуска проверять лишь когда это необходимо, без вмешательства в другие контейнеры.
